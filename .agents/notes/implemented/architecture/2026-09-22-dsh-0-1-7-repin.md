# Agent Note: The wire contract moved to dsh 0.1.7-rc.2

Status: implemented

## Problem

The client pinned `dsh-v0.1.5-rc.2` and tracked exactly one contract. The
hosts it talks to run 0.1.7, and 0.1.7 breaks the client in four places.

`subagents/list` is gone: 0.1.7's Subagent service registers only `prompt`
and `interruptByParent` (`packages/subagent/subagent/src/index.ts`). The
roster moved to the parent Session's `subagentCatalog` projection, which the
upstream Web client already reads (`ui-subagent/src/client/
SubagentHeaderLineage.tsx`) — and the client's `loadSubagents` called the
deleted route, so the Subagents screen failed outright.

`agentPresets/list` lost its per-row `trust` and its roster-level
`authorable` (`packages/preset/agent-preset-registry/src/types.ts`), because
0.1.7 took preset authoring off the Remote surface — `copy`, `deletePreset`,
`settings/openAgentPresetDirectory`, and
`settings/canOpenAgentPresetDirectory` are all gone. Both fields were
required by the decoder, so the roster threw. The same removal hit
`pluginInventory/list`'s `AgentPresetPluginGroup.trust`, which the settings
plugin section required.

`session/control` lost the `queues` and `jobs` frame types and the matching
baseline blocks (`api/session-controller/src/types.ts`). The client read both
from the baseline alone, so the queue dock and the job list would have gone
**silently empty** — the failure mode with no error in it.

`workspaceFiles/readAll` was deleted, and `readBytes` changed shape: its
third argument became `options` (`{range?, baseFile?}`), and its result now
carries native bytes through a multipart `bytes` attachment codec instead of
a base64 string in JSON.

Two failures sat under all of them. `scripts/verify_wire_pin.py` could not
parse two declaration shapes 0.1.7 introduced — `export default class … extends
TypertRemoteService` and generator methods (`async *name`) — so it failed
loudly instead of proving coverage, and the numbers it did report counted only
what it could still see. And the gate compares **names**: every payload-level
change above was invisible to it.

## Decision

Re-pin to `dsh-v0.1.7-rc.2` (`477b4f4205`) and take each replacement from the
path upstream itself took, not from the nearest thing that compiles.

- Extend the gate to parse both new declaration shapes, and record the
  derivation's blind spot (stream endpoints the client opens with a literal are
  never compared) next to the two it already documented.
- Read the roster from `session/projections` (`@Remote('projections')`) and
  decode `values.subagentCatalog`. `hasChildren` is derived from `mode`, and
  `activity` from the session roster's own `running` bit — the same two rules
  the upstream catalog dropdown uses.
- Port the deleted host function for the dock: 0.1.5's `queueItemsFromInbox`
  mapped the very same `inbox` projection the host now publishes, so the client
  reproduces it exactly (`next-turn` → `queued`, `next-step` → `steering` for a
  human and `context` otherwise, queued turns first).
- Open one `job/list` stream per followed session and republish its
  `{type: 'rows'}` frames as the `session/jobs` frame the fold owns.
- Delete `workspaceFilesReadAll`: 0.1.7 returns whole-file bytes from
  `readBytes` when `options.range` is absent. `workspaceFilesReadBytes` is
  declared and read through the multipart carrier this client now has — see
  [Workspace file previews read bytes](../feature/2026-09-28-workspace-file-byte-preview.md).
- Keep the read-only child composer working by decoding 0.1.7's new
  `SessionSummary.agentAvailable` and applying upstream's
  `selectReadOnlySubagent` rule to the child's mode, its direct parent's
  availability, and the child's own running bit.
- Fold the new `developer/message` event through the existing context-row
  path, as upstream's `developerMessageDefinition` does.

## Alternatives considered

Keep the 0.1.5 pin and declare 0.1.7 unsupported: rejected, because the hosts
this client exists to talk to already run 0.1.7, so the pin would describe a
deployment nobody has. Build the subagent roster from the client's own session
list instead of the projection: rejected, because the list carries no creation
label or mode, and both are needed to address a child for `session/page`. Keep
`readBytes` and add a multipart decoder to `http_dsh_rpc_client.dart`:
rejected as speculative — nothing in the app read whole-file bytes at the time,
so the carrier would have existed only to keep a declaration honest. The file
preview later needed exactly those bytes and the carrier landed —
[Workspace file previews read bytes](../feature/2026-09-28-workspace-file-byte-preview.md).
Keep the
diagnostic catalog rows by issuing one catalog read per child: rejected as too
expensive for a phone, and the host no longer publishes the reasons at all.
Add both deleted names to `wire_pin.declared_only_allowlist` instead of
removing them: rejected — an allowlisted name must be absent from the pin's
own registries, so the entry fails for `readBytes` (the pin registers it) and
for `readAll` (no client constant matches it); `scripts/verify_wire_pin.py`
names both cases.

## Consequences

`declared 53, upstream 125, identical 51, missing 74, client-only 2`, with 11
streams. Three capabilities are gone because the host stopped publishing them:
per-row and roster-level preset trust (the settings roster is now one flat
list with no authoring affordance), the subagent diagnostic row and its
reasons, and the catalog's `parentAvailable` hint (replaced by
`agentAvailable`). `image/offload` and
`workspace/changes` remain unrecognised by the timeline fold and are reported
as diagnostics rather than folded. Stream routes stay outside the gate's
comparison, so only the opt-in real-host tier checks that they still exist.
