# Agent Note: DSH 0.1.5 compatibility and workspace files

Status: implemented

## Problem

Upstream DeepSeek Harness (dsh) 0.1.5 introduces significant protocol and capability evolutions over 0.1.2:
1. **Session Log V3 & Canonical Envelopes**: In V3, every message-producing surface event (`system/message`, `user/message`, `assistant/message`, `tool/result`) strictly requires `surfaceOp` (`'append'` or `{ op: 'replace', startSeq, endSeq }`). The system prompt moved from `request/header.system` into Surface Node 0 (`system/message`). Mid-session prompt changes on capable DeepSeek routes append in-history `system/message` events to preserve provider prefix KV caches. The client lacked `system/message` ingestion, risking dropped prompt change context.
2. **Workspace Files service**: File inspection and reading migrated from the legacy single-method `SessionController` to the dedicated `@deepseek-ai/dsh-api-workspace-files` remote service (`workspaceFiles/read`, `readBytes`, `stat`, `list`). Mobile had no in-app file preview, leaving users unable to inspect artifacts emitted by `write` or `edit` tools.
3. **Cross-process session write leases**: DSH 0.1.5 uses kernel file locks (`flock` on POSIX, named semaphores on Windows) to prevent concurrent CLI/web writes to the same `session.jsonl`. When contested, the host returns `session-persistence/already-owned`. The client treated this as an opaque transport crash rather than a clean operational notification.
4. **Agent Teams experimental events**: DSH 0.1.5 publishes experimental team coordination (`team/*` events). These must pass through without breaking timeline deserialization.

## Decision

The Flutter client aligns with DSH 0.1.5 contracts:

- **Session V3 & In-history system prompt folding**:
  - `TimelineReducer` supports `system/message`. Node 0 (the initial system prompt on session start) is identified and suppressed from chat bubbles to preserve clean conversational transcripts.
  - In-history system prompt replacements (`surfaceOp == 'append'` or updates after Node 0) fold into `TimelineContextInjection` records with `producerLabel: 'system-prompt'`, providing inspectable notice cards titled with localized prompt-update copy.
  - Safe pass-through for unknown `team/*` events in `TimelineReducer`.
- **`workspaceFiles` Remote API integration**:
  - `DshRpcEndpoints` registers `workspaceFiles/stat`, `workspaceFiles/read`, `workspaceFiles/readBytes`, `workspaceFiles/readAll`, and `workspaceFiles/list`.
  - `DshRemoteInvoker._prepareArgs` normalizes `{ sessionId, path, range }` arguments for `workspaceFiles/*` methods.
  - Handwritten wire DTOs (`WorkspaceFileStatWire`, `WorkspaceFileTextWire`, `WorkspaceDirectoryEntryWire`, `WorkspaceDirectoryListingWire`) enforce fail-loud validation on missing required wire fields.
  - `ChatRepository` and `HarnessRepositoryImpl` expose `readWorkspaceFile`, `statWorkspaceFile`, and `listWorkspaceDirectory`.
- **Mobile file preview & deliverable artifact actions**:
  - `ToolCallRow` inspects `model.filePath` for file-modifying tools (`write`, `edit`, `read`) and renders action buttons ("Preview" and "Copy path").
  - `WorkspaceFilePreviewSheet` loads file content via `readWorkspaceFile` into a Material 3 modal bottom sheet (`kShapeSheet` radius 28), formatting Markdown files with `MarkdownText` and code/text files with monospace scrolling and line counts.
- **Flock lease error classification**:
  - `ChatController` classifies `session-persistence/already-owned` errors into `SESSION_ALREADY_OWNED`, surfaced as a localized explanation rather than an unhandled error.

## Alternatives considered

- **Render in-history system prompts as regular user or assistant bubbles**: Rejected — a system prompt is model guidance, not dialogue; presenting it as a message bubble would mislead the user.
- **Port desktop DockKit split-pane layout to mobile**: Rejected — mobile screen widths cannot comfortably fit multi-pane sidebars; a Modal Bottom Sheet matches Material 3 phone ergonomics.
- **Rely on OS default file opener**: Rejected — mobile browsers or headless hosts do not share a filesystem with the Android device; remote file bytes must transfer over the authenticated RPC seam.

## Consequences

- The client is fully compatible with DSH 0.1.5 hosts while maintaining backward compatibility with 0.1.2.
- Users can inspect files generated by coding agents directly on their Android devices without external tools.
- Mid-session system prompt updates on DeepSeek cache-stable routes are visible as fold-in context entries.
- Cross-process write contention produces actionable user feedback.
