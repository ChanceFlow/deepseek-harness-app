# Agent Note: The wire contract moved to dsh 0.2.0-rc.2

Status: implemented

## Problem

The client pinned `dsh-v0.1.7-rc.2` and tracked exactly one contract, while
upstream had already tagged `dsh-v0.2.0-rc.1`, `dsh-v0.2.0-rc.2`, and
`dsh-v0.2.1-alpha.1`. The tree-wide registration surface the wire-pin gate
derives is a superset of any one deployment's loaded plugins, so both its counts
and the pin record in [reference/README.md](../../../../reference/README.md)
described a superseded contract, and nothing else in the repository named the
newer tags.

## Decision

Re-pin to `dsh-v0.2.0-rc.2` (`639ed0153972`) and take the delta from the
reference tree rather than from a running host.

- The registered surface grows by three unary methods
  (`productAnalytics/enabled`, `productAnalytics/report`, `userQuestions/answer`)
  and two logical streams (`productAnalytics/watchPolicy`,
  `userQuestions/attachWait`). No name is removed or renamed, and every
  endpoint, stream, and event the client consumes keeps its 0.1.7 name and
  shape, so no adapter decoder or fold changes.
- `productAnalytics/enabled` and `productAnalytics/report` join the coverage
  block's `out-of-scope` list: the shipped web composition mounts the
  product-analytics rows only under the `desktop` profile
  (`packages/bundle/web-app/cordis.patch.yml`), so a `dsh web` host serves them
  to nobody, and a phone client cannot reach them at all.
- `userQuestions/answer` and `userQuestions/attachWait` stay unwired. They
  serve the 0.2.0 timed `ask_user_question`
  (`packages/interaction/tool-ask-user/src/timed.ts`), whose Cordis row
  defaults to `mode: legacy` and which no shipped bundle switches to `timed`.
  A timed host still accepts this client's waterfall answer through
  `$events/result` inside the window, so the omission costs a countdown, not the
  question. The limits are stated in [docs/spec.md §10](../../../../docs/spec.md).
- The shipped web-app bundle no longer carries any Schedule row: `time-context`,
  `schedule`, and `ui-schedule` moved into the optional
  `experimental/schedule-bundle`, which ships switched off. A stock 0.2.0 host
  therefore answers `gateway/invocation-unavailable` for the whole `schedule`
  namespace, exactly as the disabled 0.1.7 rows did.
- The gate's counts, the README coverage sentence, and the pin identity move
  with the submodule: `declared 53, upstream 128, identical 51, missing 77,
  client-only 2`, 13 streams, 31 registration sources in the digest.

## Alternatives considered

Pin `dsh-v0.2.1-alpha.1`, the newest tag: rejected — it is an alpha on a line
with no release candidate, its only addition over 0.2.0-rc.2 is the
experimental `claudeCodeMods/pressBand`, and the repository's contract is a
reproducible official tag. Stay on `dsh-v0.1.7-rc.2`: rejected — the pin exists
to describe the host line the client is deployed against, and the gate would
keep certifying a withdrawn contract. Wire `userQuestions/answer` and
`attachWait` now: rejected — nothing in the shipped composition reaches the
timed path, so both decoders would be code no host exercises. Track upstream
`master` instead of a tag: rejected — the pin is a fixed tree whose digest the
gate recomputes, and a moving gitlink makes the record unverifiable. Add all 50
unwired names to `out-of-scope` in one pass: rejected — that list records
reviewed deliberate omissions, and the rest are gaps the client may still
close, so listing them would convert backlog into policy.

## Consequences

The gate is CLEAN at the new identity and the unwired remainder grew from 74 to
77. Two new upstream capabilities are now named in the spec instead of being
invisible: desktop-only product analytics and the timed question wait. The
Schedule namespace the pin registers is served by nobody on a stock host, so a
future client surface for it has to detect that absence rather than assume the
service.
The deployed host is a downstream fork whose `dsh-v0.2.0-rc.2-chance.0` release
shares this pin's upstream base and Remote surface; its wire-neutral deltas are
recorded in [reference/README.md](../../../../reference/README.md).
This note partially supersedes
[dsh 0.1.7-rc.2 re-pin](2026-09-22-dsh-0-1-7-repin.md): its replacement
decisions stand, its pin identity and counts do not.
